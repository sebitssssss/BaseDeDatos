Historia de MySQL

Historia

MySQL nació en 1995 de la mano de la empresa sueca MySQL AB. Es un sistema gestor de bases de datos relacionales (SGBD) de código abierto que usa SQL como lenguaje de consulta.

En 2008 lo compró Sun Microsystems y en 2010 Sun fue adquirida por Oracle, que lo mantiene hasta hoy. Es muy usado en aplicaciones web (stack LAMP: Linux, Apache, MySQL, PHP).

Referentes
  • Michael "Monty" Widenius: creador de MySQL y luego de MariaDB.
  • David Axmark y Allan Larsson: cofundadores de MySQL AB.
  • Edgar F. Codd: sentó las bases del modelo relacional (1970).

Store Procedure

Un Stored Procedure es un bloque de código SQL con nombre que se guarda en la base de datos y se ejecuta con CALL las veces que haga falta. Sirve para reutilizar lógica, mejorar el rendimiento y centralizar reglas en el servidor.

DELIMITER //
CREATE PROCEDURE buscarUsuarios(IN texto VARCHAR(100))
BEGIN
  SELECT * FROM usuarios WHERE nombre LIKE CONCAT('%', texto, '%');
END //
DELIMITER ;

CALL buscarUsuarios('Fede');

SQL

Subconsultas

Un SELECT dentro de otra consulta; se usa cuando un resultado depende de otro.

SELECT nombre FROM usuarios
WHERE id IN (SELECT id_usuario FROM pedidos WHERE total > 1000);
Joins

Combinan filas de dos o más tablas relacionadas por una clave en común. Elegí un tipo:

Devuelve solo las filas con coincidencia en ambas tablas. 
SELECT u.nombre, p.total
FROM usuarios u INNER JOIN pedidos p ON u.id = p.id_usuario;
Sinónimo de INNER JOIN: si no aclarás el tipo, MySQL asume INNER. 
SELECT u.nombre, p.total
FROM usuarios u JOIN pedidos p ON u.id = p.id_usuario;
Trae todas las filas de la tabla izquierda; si no hay coincidencia, la derecha viene en NULL. 
SELECT u.nombre, p.total
FROM usuarios u LEFT JOIN pedidos p ON u.id = p.id_usuario;
Es el espejo del LEFT JOIN: trae todas las filas de la tabla derecha. 
SELECT u.nombre, p.total
FROM usuarios u RIGHT JOIN pedidos p ON u.id = p.id_usuario;
Término general para los joins que incluyen filas sin coincidencia (LEFT, RIGHT o FULL). En MySQL se escribe LEFT OUTER JOIN o RIGHT OUTER JOIN; OUTER es opcional. 
SELECT u.nombre, p.total
FROM usuarios u LEFT OUTER JOIN pedidos p ON u.id = p.id_usuario;
Trae todas las filas de ambas tablas, coincidan o no. MySQL no lo tiene nativo: se simula con UNION. 
SELECT u.nombre, p.total FROM usuarios u LEFT JOIN pedidos p ON u.id = p.id_usuario
UNION
SELECT u.nombre, p.total FROM usuarios u RIGHT JOIN pedidos p ON u.id = p.id_usuario;
Producto cartesiano: cada fila de una tabla con cada fila de la otra, sin ON. 
SELECT u.nombre, c.nombre
FROM usuarios u CROSS JOIN categorias c;
Select
Elige las columnas a mostrar.
SELECT nombre, email FROM usuarios;
From
Indica de qué tabla se traen los datos.
SELECT * FROM usuarios;
Where
Filtra filas según una condición, antes de agrupar.
SELECT * FROM usuarios WHERE id > 10;
Like
Filtra texto por patrón: % = cualquier cantidad de caracteres, _ = uno solo.
SELECT * FROM usuarios WHERE email LIKE '%@gmail.com';
Group By
Agrupa filas con un valor en común para aplicar funciones de agregación.
SELECT id_usuario, SUM(total) AS gastado
FROM pedidos GROUP BY id_usuario;
Having
Filtra después de agrupar (WHERE filtra antes).
SELECT id_usuario, COUNT(*) AS cant
FROM pedidos GROUP BY id_usuario
HAVING COUNT(*) > 5;
Order By
Ordena el resultado por una o más columnas.
SELECT * FROM usuarios ORDER BY nombre;
Asc / Desc
ASC ordena de menor a mayor (es el valor por defecto); DESC de mayor a menor.
SELECT * FROM usuarios ORDER BY id DESC;
Limit
Limita la cantidad de filas devueltas.
SELECT * FROM usuarios LIMIT 10;
Count
Cuenta filas.
SELECT COUNT(*) FROM usuarios;
Sum
Suma los valores de una columna numérica.
SELECT SUM(total) FROM pedidos;
Avg
Calcula el promedio de una columna numérica.
SELECT AVG(total) FROM pedidos;
Max
Devuelve el valor más alto.
SELECT MAX(total) FROM pedidos;
Min
Devuelve el valor más bajo.
SELECT MIN(total) FROM pedidos;
PK y FK
PK (clave primaria): identifica cada fila, no se repite ni es NULL. FK (clave foránea): referencia la PK de otra tabla.
CREATE TABLE pedidos (
  id INT AUTO_INCREMENT PRIMARY KEY,
  id_usuario INT,
  FOREIGN KEY (id_usuario) REFERENCES usuarios(id)
);
Create
Crea objetos nuevos: bases, tablas, etc.
CREATE TABLE usuarios (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(100) NOT NULL
);
Alter Table
Modifica la estructura de una tabla existente.
ALTER TABLE usuarios ADD COLUMN telefono VARCHAR(20);
Drop
Elimina un objeto completo (estructura y datos). No se puede deshacer.
DROP TABLE usuarios;
Truncate
Vacía todos los datos pero mantiene la estructura; más rápido que un DELETE sin condición.
TRUNCATE TABLE pedidos;
Delete
Borra filas específicas según una condición.
DELETE FROM usuarios WHERE id = 5;

Normalización

Organizar las tablas para reducir la redundancia y evitar inconsistencias, dividiendo la información en tablas relacionadas. Cada forma normal incluye a la anterior.

1FN Primera Forma Normal
Cada columna tiene valores atómicos (sin listas ni datos repetidos en una celda) y cada fila es única.
2FN Segunda Forma Normal
Cumple 1FN y todos los atributos no clave dependen de la clave primaria completa (importa cuando la PK es compuesta).
3FN Tercera Forma Normal
Cumple 2FN y ningún atributo no clave depende de otro atributo no clave (sin dependencias transitivas).

DER (Diagrama Entidad-Relación)

  • Usar nombres claros y consistentes (singular o plural) en tablas y columnas.
  • Definir siempre una PK por tabla.
  • Marcar bien las relaciones (1 a 1, 1 a muchos, muchos a muchos) y su cardinalidad.
  • Normalizar antes de diagramar para evitar redundancias.
  • Documentar tipos de datos y restricciones en el diagrama.
Además del clásico DER (notación de Chen, con óvalos para atributos y rombos para relaciones), el modelo se puede dibujar como diagrama de bloques: cada tabla es un rectángulo con sus columnas adentro y líneas que unen cada FK con la PK de otra tabla. Es lo que usan MySQL Workbench o dbdiagram.io, y resulta más simple de leer cuando hay muchas tablas.
